# Cinema 0.3.0 · 网页管理的 Minecraft 影院

React 管理台、Fabric 播放终端和服务器 OBS RTMP 接收端。参考 HiRender P1 的资源、节目、输出和策略工作流；独立实现，不包含其软件或界面素材。

**点播：32GB 源站盘与 R2 保存相同媒体副本，MC 使用 6 路 R2 并行预取未来 600 秒 TS，完整分片暂存磁盘；缺片距离播放不足 40 秒才用 EO，不足 20 秒且 EO 未成功才用阿里云。直播：OBS → 192.168.8.244 RTMP → FFmpeg → HLS → 源站 → EO https://live.mc.acgzjd.cn（失败后阿里云 https://live.al.mc.acgzjd.cn）→ MC；直播不上传 R2，不依赖 Workers。**

管理台包括播控台、资源库、屏幕管理、直播中心、玩家管理、流量统计和系统设置。支持播放/暂停/停止/跳转，多屏批量控制，资源上传进度、转码任务、改名、归档，世界坐标创建屏幕，以及结束保持、单片循环、队列轮播和无人暂停策略。游戏内屏幕仅播放，右键不会再打开播控菜单。

0.3.0 新增网页授权影院管理员、音频及静态图片上传播放，并已搭建 50 座林地露天影院。普通玩家创造模式、禁止建造和干扰；固定晴朗傍晚，管理员只获得本次连接的建造权限，不授予 OP。详见 [新功能与使用说明](docs/FEATURES-0.3.0.zh-CN.md)。0.2.9 的中途加入黑屏修复保留。

## 本机启动

本机已经安装 Node 24、Java 21、FFmpeg、Minecraft 1.21.1、Fabric Loader 0.16.10、Fabric API 0.116.12+1.21.1 和 Cinema 客户端/服务端 0.3.0。新版 HLS 点播采用 6 路 R2、600 秒预取和逐片 40/20 秒兜底。玩家管理和流量统计保留，RTMP 接收与 FFmpeg 转码运行在 192.168.8.244；本机客户端与服务端已同步升级。

1. 运行 `E:\mc\cinema-r2\start-console.bat`，打开 https://live.mc.acgzjd.cn 。脚本只打开网页；远端管理服务自动运行，不需要 Windows 直播后台或 SSH 隧道。
2. 运行 `E:\mc\cinema-server\start-cinema.bat`。服务端连接网页后显示“Minecraft 已连接”。
3. 在 PCL 选择 `Cinema-R2-1.21.1-Fabric`。多人游戏连接 `127.0.0.1:25565`。本机服务端已按用户要求关闭正版认证和白名单，可用离线账号进入；影院建造权限在网页「玩家管理」授予，不需要 OP；重新连接后需授权本次连接。
4. 世界出生点 `(0,104,36)`；主影院控制器 `(0,100,-8)`，面向南。勾选主影院，选择资源，点击“立即播放到 N 块屏幕”。“载入待播（暂停）”用于提前准备；中间的播放/暂停/跳转只控制当前节目。

PCL 位于 `E:\PCL 正式版 2.13.0.1\plain craft launcher 2.exe`。影院实例通过目录联接接入其默认游戏目录；无需再扫描用户 Documents 文件夹。

管理台已部署到 192.168.8.244 的 /mnt/cinema 独立 32GB 盘，公网入口为 https://live.mc.acgzjd.cn。MC 管理桥与媒体使用公网 HTTPS；MC 游戏服务本身仍监听 127.0.0.1:25565，外部玩家进服还需要单独配置可达的游戏地址。OBS 接收与转码已迁到 192.168.8.244:1935。

## 资源与 R2

现有有本地原片的素材可在资源管理中生成 720p/1080p 独立副本，不覆盖当前素材；新副本按 R2 预算检查。原片只有 720p 时不能产生真正的 1080p 细节。

在资源库上传 MP4、MKV、MOV 或 WebM 视频，MP3/WAV/FLAC/OGG/M4A/AAC 音频，PNG/JPG/WebP 静态图片，单文件限制 4 GiB。音频配音乐画面；图片展示时长可设 1–3600 秒，保持比例补边，可保持或轮播。默认转换为 HLS：H.264/AAC、24 fps、12 秒独立分片，可选 720p 或 1080p（不放大低分辨率原片）。MP4 模式会兼容重封装并前置索引；不兼容编码会在服务器转码。处理完成后自动发布到 R2；没有凭据时先保存为源站资源。

选中素材仅更新左侧“下一条素材”。点击“独立预览素材”打开单独视频控件，不改变屏幕节目。预览默认静音，可开启声音。“载入待播（暂停）”加载素材并暂停；“立即播放到 N 块屏幕”以一条原子指令加载并播放。中间始终显示参考屏幕的当前节目，所有运输按钮只控制当前节目。进度与策略以所选第一块屏幕为参考，按钮对所有勾选屏幕执行。

64 MiB 以下使用单次上传；较大对象用 64 MiB 分段上传，失败中止未完成的 multipart。HLS 点播先上传片段，最后发布清单。原文件和转码副本留在 192.168.8.244 的 32GB 盘，上传 2–3 GB 影片前应留足磁盘空间和转码时间。

本机 R2 绑定 `video` 桶，公共域名 `https://video.mc.cxmlbt-tec.top` 已启用。知道资源链接的人可以读取媒体。网页预览 CORS 仅允许 localhost/127.0.0.1 的 3210/3211 端口 GET/HEAD；运行后台的 S3 对象读写凭据保存在 `/mnt/cinema/cinema/data/settings.json`，不会发给玩家或前端。当前凭据仅限 `video` 桶，有效期至 **2027-04-09**，到期需在系统设置更新。

上传前按整个桶的已完成对象计算默认十进制 8 GB 预算；此检查不覆盖其他桶、其他上传者并发写入或历史操作量。R2 免费额度由账户共享，直连没有 Workers 每日请求上限保护，不能保证全账户永不计费。系统设置可以调整预算。资源归档保留本地和 R2 文件，**不释放云端空间**；若需要清理云端影片，先停止相关屏幕播放，再在 R2 控制台确认删除相应资源目录。

旧 `cinema-media` Worker 已停用，本版不依赖它。`gateway/` 和旧上传工具为 0.1 版本留档；历史说明见 `docs/LEGACY-0.1.0.zh-CN.md`，不代表当前配置。

## OBS 直播直接分发

1. 直播中心点击“启动直播接收”。
2. OBS 设置 → 直播 → 自定义，服务器 `rtmp://192.168.8.244:1935/live`，推流密钥使用网页“显示”按钮取得。勿把密钥发给观众。
3. 推荐 H.264/AAC、关键帧间隔 2 秒；点击 OBS 开始直播。
4. 等待网页出现直播画面；回到播控台，选“OBS 直播”，发送至屏幕，再开始播放。

192.168.8.244 上的后台只转码一次。直播输出可选 720p/1080p、24 fps，在系统设置中选择；下一次 OBS 推流生效，4 秒/片，清单保留 8 片；旧片段滚动在服务器清理。MC 各自通过 EO https://live.mc.acgzjd.cn（故障时阿里云 https://live.al.mc.acgzjd.cn）获取 HLS，不经过 R2。暂停直播屏幕时保持当前画面；恢复后回到直播目标延迟，不支持点播式跳转。

公网直播地址为 `https://live.mc.acgzjd.cn/live/<直播ID>/index.m3u8`。直播清单缓存 1 秒，TS 缓存 86400 秒；每次推流用微秒起始编号，避免重启复用旧片名。HLS 直接保存在 /mnt/cinema/cinema/data/live，源站无需再连接 Windows 或 SSH 隧道；观众只访问公网 HTTPS 域名。现有 OBS 密钥已保留，只需更换推流服务器。局域网推流已验收，公网 RTMP 尚未配置 TCP 端口映射。网站 CDN 分发 HLS，不能用网站 HTTPS 地址直接接收 RTMP。

## 双副本、故障回退与流量策略

资源上传转码后保留本地成品，发布相同目录到 R2。远端启动和每小时自动校验，资源库“同步 R2 / 源站”可手动重试。缺本地文件从 R2 补齐，缺 R2 对象从本地补齐；上传先片段后清单，校验长度、可用 ETag/保存的 SHA256。两端内容冲突时不覆盖，阻止该资源继续走源站回退；外链及直播不进入双副本同步。同步不会删除或自动导入未登记的桶内文件。

MC 0.2.8 在 libmpv 前使用私有回环适配器，上游使用公网 HTTPS。点播 HLS 调度器最多同时下载 6 片 R2 TS，覆盖当前位置至未来 600 秒；下载可乱序完成，完整文件原子发布到磁盘，libmpv 按清单顺序读取。R2 失败按 1/2/4/8 秒持续重试，单次最多 120 秒。只有缺片开始时间距实际播放不足 40 秒才允许 EO，不足 20 秒且 EO 已失败或等待至少 1.5 秒才允许阿里云；EO 提前失败不会放宽阿里云时间门限。起播和未缓存跳转处的片段已经到期，可立即补片。同片先成功的渠道取消其他请求，缓存命中不重新下载。EO/阿里云各有 1 个补片槽，独立于 6 路 R2。跳转取消旧窗口任务并保留新窗口内的完整片段。

新版 TS 磁盘预算 `segmentCacheMB` 默认 2048 MiB，范围 256–8192，包含在途预留并保留至少 1 GiB 可用空间；不足时不能保证填满 600 秒。它另加于 libmpv 自身缓存，关闭播放会话后清理随机临时目录。单片最多 32 MiB。MP4 Range 与旧客户端保留原 60 秒 CDN 起播、30 秒缓存兜底策略；直播仍只走 EO → 阿里云。外部清单、加密 HLS 和跨目录分片不进入受控调度器。详见 [0.2.8 缓存策略](docs/DELIVERY-0.2.8.zh-CN.md)。

客户端设置：`r2Failover=true`、`primaryMediaBase=https://video.mc.cxmlbt-tec.top`、`cdnMediaBase=https://live.mc.acgzjd.cn`、`backupMediaBase=https://live.al.mc.acgzjd.cn`、`cdnTimeoutSeconds=6`、`primaryTimeoutSeconds=6`（2–30 秒）。网页“系统设置”可设置 TS 预取范围与 EO/阿里云逐片窗口；MP4 与旧客户端兼容设置保留原起播/兜底参数，也可关闭 CDN/点播使用，单独关闭最后备用源，配置两家 CDN 合计的单日、单月、单次播放用量预算；0 表示未设限，不表示免费额度。策略请求也按 EO → 阿里云回退；两者都失败且策略过期时关闭 CDN，正常 R2 点播仍可读取。

统计仅计入新版 MC 客户端上报的下载字节，包含 CDN 缓存命中，排除网页、其他访问和未上报量；按 UTC 日/月累计。这是辅助预算，不是两家 CDN 的账单或硬封顶，缓存对象及在途请求仍可能被获取。EO 免费计划的官方支持范围排除视频与大文件分发，不能以“免费流量不限”保证本影院免费运行：[官方套餐说明](https://edgeone.ai/zh/document/70405?product=pricing)。R2 的 8 GB 预算继续生效，32GB 本地盘同步保留 1 GiB 剩余空间。

## 阿里云 CDN 最后保障

备用域名 `https://live.al.mc.acgzjd.cn` 已接入，HTTPS 回源 `home.cxmlbt-tec.top:39994`，该源域名仅解析 AAAA，开启 IPv6 回源优先；回源 Host 和 SNI 均为 `home.cxmlbt-tec.top`。客户端默认备用域名与后台设置保持一致，修改地址时需同步各玩家客户端配置。

边缘使用独立 Let's Encrypt RSA 2048 证书，HTTP 301 跳转 HTTPS，HTTP/2、OCSP、TLS 1.2/1.3 开启，TLS 1.0/1.1 关闭。证书有效期至 **2027-01-08 10:51:35（UTC+8）**，目前没有自动续期，需在到期前重新签发并在阿里云替换。专用私钥和 ACME 账户只在本机私有 `.tools/cdn-tls` 内保存，不包含在发布包中；阿里云持有该域名专用私钥。

缓存从高到低：`/api/` 0 秒；`/media/` 点播目录 86400 秒；`m3u8,mpd` 清单 1 秒；`ts,mp4,m4s,m4a` 86400 秒；默认 `/` 0 秒。点播清单由 `/media/` 高优先级规则缓存一天；直播清单持续更新。保留源站 no-store，启用 512KB Range 回源。现有完整媒体和 epoch 唯一直播片名不覆盖，避免同名旧缓存。

React 管理台对资源、屏幕修改和移除使用同等认证的 POST `/update`、`/remove` 接口，兼容阿里云 CDN 不支持 PATCH/DELETE 的限制。MC 管理桥主连接故障时也使用备用域名，失败主源 30 秒后重试；指令回执和去重机制保留。两条 CDN 都回同一个源站，因此这个回退保护 CDN 访问故障，源站故障仍会同时影响两条线路。

阿里云 HTTPS 请求计费已按用户授权开启，流量按用户已购买的 CDN 套餐计费。流量统计分别显示 EO 与阿里云字节，预算仍合并累计；客户端上报不能单独反映阿里云账单，也不能保证账单硬封顶。配置证据见 `dist/paid-cdn-validation-0.2.5.json`；证书续期步骤见 `docs/CDN-0.2.5.zh-CN.md`。

## 玩家管理与流量统计

玩家管理每两秒更新在线/历史/封禁名单，显示 UUID、延迟、维度、坐标、游戏模式、观影状态、缓存和下载量。支持传送到已在线屏幕的安全落点、踢出、封禁和解封，操作需确认并等待 MC 执行回执；不提供任意控制台命令或 OP 授权。封禁使用 Minecraft 原生名单，重启后保留。历史最多保存最近 2000 位玩家；离线模式 UUID 不代表经过验证的正版身份。

流量统计按 R2、EO、阿里云及旧版未分类 CDN 展示日/月/升级后累计用量、最近 30 秒上报速率、最近 31 天/168 小时趋势、玩家下载排行和每日 CSV。身份由已认证 MC 桥提供，播放器上报使用签名会话并按累计差值去重。已有磁盘缓存的重复播放无需下载，不产生新的网络用量。旧 CDN 账目保留为未分类，不能追溯分配给玩家或线路；R2 详细趋势从升级后开始。统计仅覆盖新版 MC 实际上报的媒体字节，不代表云端账单。详见 docs/OPERATIONS-0.2.6.zh-CN.md。

## 屏幕与同步策略

世界内放置 `cinemar2:screen` 会自动登记。网页也可在已加载的空位置按坐标创建屏幕，宽度 4–32 格、16:9，控制器位于屏幕下沿中心。网页可改名、尺寸、方向、策略或移除屏幕；离线取消登记后，区块重新加载会再次自动发现。

服务器维护点播时间轴，命令立即广播，附近观众每两秒接收例行状态；晚加入从当前进度开始。时钟校准和有限次数纠偏用于缓解网络漂移。媒体连接失败或长时间无帧时有限重试，避免无限请求。桥接每 250ms 检查命令，网页每 400ms 更新状态；指令回执与近期 ID 去重避免误报成功，HTTP 等待不阻塞 MC tick。附近客户端每秒回报实际位置、缓存量、缓冲及错误；网页区分目标进度与游戏实际进度，不再把服务端播放状态当作客户端已经显示画面。浏览器参考画面跟随一个客户端的回报，不是游戏画面回传，也不能代表所有观众逐帧一致。无人世界中播放策略仍检查，服务器重启按暂停恢复。一个控制台同时接入一个 MC 服务端。

队列先添加素材、同步到选定屏幕，再将结束策略设为顺序轮播。直播目标延迟默认 12 秒，按分片选取起始位置；不同客户端可能存在分片/缓冲级误差，**不保证逐帧同步**。无人暂停根据同维度 64 格范围内的玩家数量判定。

客户端 0.2.9 使用 **libmpv**。内核负责网络预读、HLS 解复用、音视频同步、硬件解码回退和音频设备输出；模组通过软件渲染 API 取得一张 RGB 帧并整帧上传 MC 纹理。软件渲染 API 不等于禁用硬件解码：本机实测启用 d3d11va-copy，将解码帧回读到内存再上传纹理；不是 GPU 零拷贝。

在“屏幕与播放策略”选择 720p 或 1080p；点播默认预读上限 1200 秒，范围 30–3600 秒，默认起播/重新缓冲等待 20 秒，可调 1–120 秒。网络速度决定实际能缓冲多少，设置上限不代表立即预读完成。缓冲不足时保留画面，交给 libmpv 等待恢复；不会因为没有新帧而不断清空缓存。服务端时间同步通过小幅调速及必要的定位追赶，缓冲期间不强制定位；低速玩家可能暂时落后，不能保证逐帧同步。

默认启用点播磁盘缓存，缓存目录 `E:/mc/cinema-cache`，关闭该媒体时由 libmpv 删除临时文件。缓存文件是追加写入，播放和跳转累计数据会增长；达到约 8 GiB 时切换到内存缓存（一次读取/轮询可能略超上限），已有磁盘文件保留到关闭媒体。磁盘空间不足以容纳预算与额外 2 GiB 时改用内存缓存。`cacheMemoryMB` 默认 512、范围 64–4096；开启磁盘缓存时，该值主要约束包元数据，**不是磁盘媒体数据大小上限**。播放器及系统还有解码帧等其他内存开销。`diskCache`、`cacheDiskGB`（1–64）和 `cacheDirectory` 在客户端配置中设置。

直播使用 30 秒预读上限和 4 秒起播缓冲，目标延迟仍由屏幕策略设定；直播只取得已经发布的片段，不能预读未来内容。点播暂停、恢复、跳转以及尺寸/片尾策略修改会复用播放器及缓存，不重新等待首播缓冲。缓存内跳转可直接定位；未缓存位置仍需网络读取。切换资源地址、清晰度、缓存配置或退出屏幕范围会关闭旧会话缓存；直播暂停冻结画面，恢复重新接入直播。缓存不是永久离线资源。

每个客户端同时解码最近的一路节目；同一路节目、近似同一进度的多块屏幕共享纹理。不同节目的屏幕以最近屏幕为优先。游戏画面可调 1280×720 或 1920×1080，按媒体帧率播放，libmpv 系统音频输出，距离衰减；暂不提供字幕、全员准备倒计时或 MC 音量滑杆集成。

## MC 服务端接入现有网站后台

希望将自己的 MC 服务端接入现有 `https://live.mc.acgzjd.cn`（备用 `https://live.al.mc.acgzjd.cn`）后台时，先联系维护者申请接入，由维护者私下交付桥接令牌，并确认切换时间。**当前后台同时只支持一个活动中的 MC 服务端**：已有实例在线时，另一实例收到 `409 控制台已连接另一个 MC 服务端`；更换 `serverId` 只改变显示名称，不能实现多服务器隔离。

1. 安装 Minecraft 1.21.1 Fabric 服务端、Fabric API 和 `cinema-r2-0.3.0.jar`，用 Java 21 启动一次生成配置，再正常停止。
2. 在 MC 服务端工作目录的 `config/cinemar2-server.json` 填写下面配置。地址用域名根地址，不加 `/api`；真实令牌必须替换示例。

```json
{
  "allowedMediaHosts": ["video.mc.cxmlbt-tec.top", "live.mc.acgzjd.cn", "live.al.mc.acgzjd.cn"],
  "viewDistance": 64,
  "managementUrl": "https://live.mc.acgzjd.cn",
  "managementFallbackUrl": "https://live.al.mc.acgzjd.cn",
  "managementToken": "替换为维护者私下提供的桥接令牌",
  "serverId": "my-cinema",
  "allowLocalMedia": false,
  "protectCinema": true
}
```

3. 服务端需能出站访问管理域名 HTTPS/443，不需要暴露一个供后台调用的 HTTP 控制端口。维护者停止原 MC 服务端后，后台约 6 秒无旧心跳才允许切换；随后启动自己的实例，由维护者检查网页「Minecraft 已连接」、服务端名称与屏幕状态。配置改动后需重启 MC。没有屏幕时可在网页创建，随后选择素材、发送到屏幕并播放。
4. 观众使用该实例的 MC 游戏地址进服，客户端安装相同模组、Fabric API、Java 21 和 libmpv 原生库；客户端默认媒体地址已是上述 R2/EO/阿里云域名，已有旧配置需核对。网站地址用于管理及媒体，不能替代游戏进服地址。MC 服务端无需 R2 凭据、网页登录密码或 libmpv。

MC `managementToken` 必须匹配网站后台私有 `settings.json` 的 `bridgeToken`；源代码与 Release 没有维护者真实令牌。网页控制另需向维护者申请网站管理密码。桥接令牌可接入整个后台，没有按服务器划分权限；不要在 GitHub、聊天群或给玩家的配置中公开它。未授权时接口返回 `401 Bridge 未授权`；空令牌或空管理地址时模组不发起连接。持有正确令牌也不能绕过上述单活动实例限制。

接入前确认 `protectCinema=true` 适合自己的世界：它开启专用影院的创造模式、固定晴朗傍晚和全服务端建造/实体/爆炸保护。连接网站不会自动搭建场景；网页「搭建/重建场景」会覆盖主屏周围有限区域，先备份世界再执行。若需多台独立 MC 服务器同时接入，须扩展后台；当前版不能仅靠复制配置实现。

## 其他机器开发与部署

以下用于自建网站后台。独立部署应使用自己生成的桥接令牌，并替换管理域名、媒体域名和客户端默认地址；不要将自己的后台令牌误填到项目维护者的网站地址。

运行环境：Node 22.12+（本机用 24）、Java 21、FFmpeg/FFprobe。管理台与直播转码需要 FFmpeg；MC 观众客户端需要 libmpv 原生库；服务端不需要 libmpv。MC 专用服务端只同步控制数据，不拉取电影。

```powershell
cd console
npm ci
npm run build
npm start
```

首次启动生成 `console/.data/settings.json`；保存资源、配置和密钥的 `.data` 不应提交或分发。将其中 `bridgeToken` 写入 MC 服务端 `config/cinemar2-server.json`：

```json
{
  "allowedMediaHosts": ["r2.example.com", "cinema.example.com", "backup.example.com"],
  "viewDistance": 64,
  "managementUrl": "https://cinema.example.com",
  "managementFallbackUrl": "https://backup.example.com",
  "managementToken": "填写自己的后台生成的 bridgeToken",
  "serverId": "主影院",
  "allowLocalMedia": false,
  "protectCinema": true
}
```

上面的 `example.com` 地址须替换为自己的 HTTPS 域名；没有备用管理入口时将 `managementFallbackUrl` 留空。客户端 `config/cinemar2-client.json` 的 `primaryMediaBase`、`cdnMediaBase`、`backupMediaBase` 也须对应自己的 R2 和 CDN 媒体入口，后台的媒体地址、CORS 与受信任来源一并按自己的部署配置。

`allowLocalMedia` 仅允许回环 3210 端口用于联调；远程媒体应使用 HTTPS。服务端和观众只需相同的 `cinema-r2-0.3.0.jar`、Fabric API 与相应运行环境。**不要分发管理端 `.data` 或含 bridgeToken 的服务端配置。** 客户端 `cinemar2-client.json` 中配置 `mpvLibraryPath`（本机为 `E:/mc/runtime/libmpv-20261009/libmpv-2.dll`）、`volume` 和缓存参数。旧 `ffmpegPath`、`bufferSeconds` 不再控制 MC 播放。

Windows x64 可运行 `tools/install_libmpv.ps1` 下载固定版本并核对 SHA256，需要已安装 7-Zip；也可从 [mpv 安装页](https://mpv.io/installation/) 指向的 Windows 构建下载 **mpv-dev** 包，解压后将 `mpvLibraryPath` 指向 `libmpv-2.dll`。不会只安装 mpv.exe。JNA 绑定随模组 JAR 打包；原生库不包含在 JAR 中。第三方来源见 `THIRD_PARTY.md`。

验证命令和实际范围见 `VALIDATION.md`。本机功能与媒体链路已验收，尚未进行两台真实玩家客户端的画面/音画差异验收，也未进行 50–100 人负载测试。
